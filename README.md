# Watcher TGWS independent update channel

Отдельный публичный репозиторий только для автоматической сборки Windows x64 CLI из официальных стабильных релизов Flowseal/tg-ws-proxy. Не загружайте сюда полный Watcher Alerts, диагностические архивы, `.env`, профиль, сессии, закрытые ключи. Исходники прокси и оригинальная лицензия MIT: https://github.com/Flowseal/tg-ws-proxy. Каждый опубликованный пакет содержит UPSTREAM-LICENSE.txt и указывает точный upstream commit в подписанном манифесте.

Каждые 6 часов workflow проверяет официальный релиз, пропускает уже опубликованные версии, получает исходники по SHA коммита, собирает CLI через Nuitka, проверяет версию, обязательные параметры и запуск локального TCP listener (обычный режим и --no-secure). После упаковки тестирует извлечённый пакет через тот же VersionStore, который используется клиентом. Только затем отдельный runner подписывает манифест Ed25519 и публикует полный GitHub Release. Закрытый ключ не доступен job сборки. Пакеты не заменяются поверх существующей версии. При ошибке workflow не публикует новую версию. Тест локального listener не подтверждает реальную доставку сообщений Telegram.

## Настройка один раз

См. `TGWS_AUTOMATION_SETUP_RU.md` в архиве Watcher для подробной инструкции. Кратко: создать публичный репозиторий, загрузить содержимое этой папки, создать ключ и доверенный конфиг командой `python tools/channel.py setup`, добавить Actions secret `TGWS_SIGNING_KEY` и variable `TGWS_PUBLIC_KEY`, запустить workflow вручную впервые. Последующие запуски по расписанию. Приватный PEM держать вне репозитория и архива Watcher. GitHub не гарантирует точное время schedule; в публичных репозиториях расписание может отключиться после 60 дней отсутствия активности. Если сборка завершилась ошибкой, откройте Actions; если остался незавершённый draft релиза, удалите только этот неопубликованный draft и перезапустите workflow. Не удаляйте рабочие релизы. Защитите основную ветку, доступ к репозиторию и аккаунт (2FA). Используются официальные Actions с major-version refs и зависимости upstream, которые могут измениться; это доверенный CI, а не независимый аудит безопасности upstream.
